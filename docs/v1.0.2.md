# Betrieb und Migration 1.0.2

## Docker

Docker Engine/Compose müssen Named-Volume-Subpaths unterstützen. `bash scripts/compose.sh config` prüft die Konfiguration, ersetzt aber keinen Laufzeittest. Neue leere Volumes erhalten public/ und meta/ aus dem Backend-Image mit UID/GID 65532. Vorhandene Volumes müssen passende Rechte besitzen. Default-Volume: nginx-html-manager-html-data; HTML_VOLUME_NAME in .env kann den Namen ändern. `down` erhält Daten; `down -v` löscht sie. Passwort bleibt ein separates Dateisecret.

Neustart ohne Datenmigration zeigt einen leeren Datenbestand. Vor dem Wechsel alten Stack stoppen, public/ UND meta/ sichern und gemeinsam migrieren. Folgende Befehle gelten für den Default-Volume-Namen; bei eigenem Namen anpassen:

```bash
bash scripts/compose.sh down
tar -czf "html-data-backup-$(date +%Y%m%d-%H%M%S).tgz" data
bash scripts/compose.sh build
bash scripts/compose.sh run --rm --no-deps uploader init-storage
GO_IMAGE=$(sed -n 's/^GO_IMAGE=//p' images.lock.env)
docker run --rm --user 0:0 --entrypoint /bin/sh \
  --mount "type=bind,src=$PWD/data,dst=/source,readonly" \
  --mount type=volume,src=nginx-html-manager-html-data,dst=/target \
  "$GO_IMAGE" -ec '
    test -d /source/public && test -d /source/meta
    test -z "$(find /target -mindepth 1 ! -type d -print -quit)"
    cp -a /source/. /target/
    chown -R 65532:65532 /target
    chmod 755 /target /target/public /target/meta
  '
bash scripts/compose.sh up -d --wait
```

Migration nutzt kurzzeitig den per Digest fixierten Go-Builder als root. Ziel darf keine Dateien enthalten. Unterbrochene Kopie manuell prüfen, nicht blind wiederholen. Alte data/-Quelle und Backup bis zur erfolgreichen Abnahme behalten. Secret separat verschlüsselt sichern. Zum Rollback neue Volume-Daten zurückkopieren. Bei Docker-Uploads über 6 MiB auch client_max_body_size in nginx/nginx.conf erhöhen.

## Kubernetes

Chart: charts/nginx-html-manager. Genau ein Pod mit Backend und NGINX; Recreate vermeidet überlappende Writer. Go verwendet 8080, NGINX Admin 8082 und Public 8081; Service Admin 8080 verweist auf 8082. NGINX mountet nur public/ read-only. init-storage erzeugt Unterverzeichnisse vor dem Subpath-Mount.

Beide Images bauen, testen, scannen und in eine erreichbare Registry pushen. local/-Defaults sind KEINE veröffentlichten Registry-Images. Beispiel:

```bash
make init lock build test scan chart
docker tag local/html-manager:1.0.2 registry.example.test/html-manager:1.0.2
docker tag local/html-manager-nginx:1.0.2 registry.example.test/html-manager-nginx:1.0.2
docker push registry.example.test/html-manager:1.0.2
docker push registry.example.test/html-manager-nginx:1.0.2
kubectl create namespace html-manager
kubectl -n html-manager create secret generic html-manager-admin \
  --from-file=admin_password=secrets/admin_password.txt
helm upgrade --install html-manager charts/nginx-html-manager \
  -n html-manager \
  --set image.backend.repository=registry.example.test/html-manager \
  --set image.nginx.repository=registry.example.test/html-manager-nginx \
  --wait --timeout 5m
kubectl -n html-manager port-forward svc/html-manager 8080:8080 8081:8081
```

Browser-Origins müssen zu values.yaml passen. auth.existingSecret und passwordKey konfigurieren; niemals Passwort als --set speichern. imagePullSecrets für private Registries, optional image.*.digest für verifizierte Digests.

persistence.size: 5Gi; storageClass null: Clusterdefault, "": keine Klasse, Name: explizite Klasse. existingClaim nutzt bestehenden PVC. fsGroup 65532 muss vom Storage/CSI unterstützt werden; Altbestände ggf. administrativ korrigieren. PVC bleibt bei uninstall standardmäßig erhalten; bei Neuinstallation retained PVC als existingClaim angeben. Expansion benötigt StorageClass-Unterstützung. Keine automatische Datenmigration oder Schrumpfung. Für konsistente Backups Deployment auf 0 skalieren, public/ und meta/ sichern, wieder auf 1 skalieren; Secret separat sichern.

Ingress braucht zwei verschiedene Hosts, passende HTTPS-Origins und TLS-Secret:

```yaml
config:
  adminOrigin: https://admin.example.test
  publicUrl: https://pages.example.test
ingress:
  enabled: true
  className: nginx
  adminHost: admin.example.test
  publicHost: pages.example.test
  tls:
    - secretName: html-tls
      hosts: [admin.example.test, pages.example.test]
```

TLS-Secret/Zertifikat selbst bereitstellen. HTTPS-Redirect, HSTS, Upload-Limit und Rate-Limits am Ingress-Controller konfigurieren. Admin möglichst nur über VPN/interne Netze. Keine automatische Zertifikatsverwaltung oder NetworkPolicy enthalten. Die Public-CSP bleibt restriktiv. Kein direkter Backend-Port im Service.
